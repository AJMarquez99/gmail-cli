# Audit: v1.0.0 staging hands-on test

**Date:** 2026-06-26 · **Build under test:** `origin/staging` @ `c36fdd2` (v1.0.0, PRs #16+#17
merged) · **Method:** global install from the `staging` working tree (`npm install -g .`), exercised
against a live Gmail account (default profile, unrestricted capabilities) · **Tester:** maintainer +
agent, interactive session.

## Verdict

v1.0.0 is **feature-complete and functionally correct** across the exercised surface. **Two release
blockers** were found; both are small, isolated, and have documented fixes. **Do not tag `v1.0.0`
until both clear.** Everything else passed.

## Findings (blockers)

1. **IMAP connections can hang indefinitely** — no connect/socket/greeting timeout on the IMAP
   client, so any IMAP command can stall forever instead of erroring (recovers on retry, so it reads
   as intermittent). Observed twice (`doctor` cold start; a `label remove`). Fix: set imapflow
   timeouts in the client constructor. → `.ai/notes/imap-connection-timeout-hang.md`
2. **`draft create` drops aliased recipients** — `draft create --to <alias>` saves a draft with an
   empty `To:` (alias not expanded → recipient silently lost), which also breaks the downstream
   `draft send`. Same bug class as the PR-#16 forward/reply alias finding, in a path Phase 5 didn't
   re-check; verified isolated to `draft create` (forward/reply/send expand correctly). Fix: route
   `runDraftCreate` through `resolveRecipients` with enforcement off. →
   `.ai/notes/draft-create-alias-not-expanded.md`

## Coverage gaps (untested — low risk)

Not exercised; judged low-value as they are thin wrappers over already-verified primitives or minor
variants: `archive` / `move` / `trash` real mutations (same IMAP primitives as the verified
`label`/`mark` path), real `draft send`, real `reply` send, `reply --all` (cc derivation),
`read download` (attachment basename sanitization). Worth a quick pass post-fix if time allows;
none expected to surface new logic bugs.

## Recommendation

Fix both blockers (TDD), re-verify the two affected paths (a draft-alias round-trip; a
connection-timeout/fail-fast check), then proceed with the release mechanics: tag `v1.0.0` →
publish-on-tag CI → promote `staging` → `main`.
